# Internationalization (i18n)

The web app is localized with [`use-intl`](https://next-intl.dev/docs/environments/core-library), the framework-agnostic core of next-intl, and the user-facing README has a copy in every UI locale. This doc covers where strings live, what we translate and what we leave in English, how to add a language, and how to keep the translated READMEs in sync.

## Quick map

| Layer | Source of truth | Notes |
|---|---|---|
| UI strings | `apps/web/messages/{locale}.json` | English is bundled eagerly; other locales lazy-load as chunks (`apps/web/src/i18n/provider.tsx`) |
| Locale list + names | `apps/web/src/i18n/locales.ts` | Also does `navigator.languages` best-match detection |
| Locale persistence | `localStorage('locale')` | Client-side setting; URLs carry **no** locale prefix |
| Locale-aware navigation | `apps/web/src/i18n/navigation.ts` | `href`-based `Link`/`usePathname` compat over TanStack Router |
| Date / time / number formatting | `useFormatter()` | Use it for anything the user sees |
| User-facing README | `README.md` (en, repo root) + `docs/i18n/README.{locale}.md` (all others) | One language strip at the top of each |
| README translation sync | `docs/i18n/.translation-status.json` | The English README's hash, plus the hash each locale was last synced at; checked by CI |

## Translation policy

What we translate: every UI string, plus the user-facing `README.md`. UI strings means navigation, page headers, empty states, toasts, form labels and validation messages, button text, breadcrumbs and ARIA labels.

What we deliberately *don't* translate:
- **Developer docs** (`AGENTS.md`, `CONTRIBUTING.md`, everything under `docs/` except the translated READMEs, `CHANGELOG.md`). Translating them would double the work on every doc PR.
- **MediaMTX field labels** in the MediaMTX config form (`apps/web/src/features/mediamtx-config/sections.ts`). They are MediaMTX's own YAML keys (`rtspAddress`, `hlsServerCert`), and translating them breaks the link to MediaMTX's documentation. Section titles, help text, the save bar, toasts and buttons *are* translated.
- **PWA manifest name/short_name** (`apps/web/public/manifest.webmanifest`). "MediaMTX Connect" is the same in every locale.
- **Brand names and protocols**: "Connect", "MediaMTX", "RTSP", "RTMP", "HLS", "WebRTC", "SRT".
- **Log messages.** Logs are for operators and stay in English.

## Supported locales

There are 30 locales, all at 100% key parity with `en.json` (CI-enforced): `en` (source of truth), `es`, `zh` (Simplified), `it`, `de`, `ru`, `fr`, `pt`, `ja`, `pl`, `ko`, `tr`, `nl`, `cs`, `zh-tw` (Traditional), `pt-br`, `id`, `ro`, `sv`, `da`, `no`, `fi`, `el`, `hu`, `uk`, `vi`, `tl`, `th`, `hi`, `bn`.

The non-English catalogues and the translated READMEs were machine-translated and nobody fluent has reviewed them. A fix from a native speaker is always welcome.

The locale is a client-side setting. It starts from `navigator.languages`, the language button in the header switches it, and `localStorage` remembers the choice.

## Adding a new language

1. Add the locale to `locales` and `LANGUAGE_NAMES` in `apps/web/src/i18n/locales.ts`.
2. Copy the source file: `cp apps/web/messages/en.json apps/web/messages/xx.json`.
3. Translate every value in `messages/xx.json`. Don't delete or rename keys; `pnpm i18n:check` enforces parity with `en.json`.
4. Translate `README.md` into `docs/i18n/README.xx.md`. Prefix repo-root links with `../../` (`../../LICENSE`, `../../docs/FEATURES.md`) and link sibling locales as `./README.{other}.md`; English is `../../README.md`.
5. Add the language to the strip at the top of `README.md` (`./docs/i18n/README.xx.md`) and of every `docs/i18n/README.*.md` (`./README.xx.md`), bolding the current one.
6. Add `"xx": "<sourceHash>"` to `translations` in `docs/i18n/.translation-status.json`, using the current `sourceHash`.
7. Update the locale list in `docs/FEATURES.md` §9 and in this file.
8. Run `pnpm verify`.

## When `README.md` changes

`pnpm i18n:check:readme` (`scripts/readme-i18n-check.mjs`, part of `pnpm i18n:check` and so of `pnpm verify` and CI) fails as soon as `README.md` changes. Translate the change into every `docs/i18n/README.{locale}.md` in the same PR, then set `sourceHash` and every locale's hash in `.translation-status.json` to the new value the script prints (the first 16 hex characters of `sha256(README.md)`).

Bumping the hashes alone isn't enough. The script also compares each translation's structure against the English: the heading outline, the language and line count of every fenced block, and every literal in backticks must match. A README edit that adds a heading, a code line or a backticked literal stays red until every locale carries it.

Code blocks, commands, env var names, URLs, file paths, product and protocol names, and MediaMTX config keys stay in English in every translation.

## Conventions

- **One namespace per surface**: `Nav`, `Common`, `Forms`, `Streams`, `Recordings`, `Config`. Add a namespace when you add a feature folder.
- **Key style**: dot-nested camelCase. Write `Streams.empty.noStreamsTitle`, not `streams_empty_no_streams_title`.
- **ICU placeholders, not concatenation**: `"onlineSince": "Online since {date}"`. Plurals use ICU's `{count, plural, one {...} other {...}}` syntax.
- **Rich text via `t.rich`** when copy embeds an element: the message uses a placeholder tag (`"Set <code>record</code> on the path"`) and the call site supplies the renderer (`t.rich('key', { code: chunks => <code>{chunks}</code> })`).
- **No raw string literals in JSX** under `apps/web/src/features/**` and `apps/web/src/components/**`. Lint enforces this for text, `title`, `alt` and `aria-label`; shadcn primitives in `components/ui/` are exempt. It misses units built in TypeScript (`"MB"`, `"h"`), so pass those through `useFormatter()` instead.
- **`<html lang>` follows the active locale.** `I18nProvider` sets it on switch.
- **Format dates with `useFormatter()`**, not `dayjs`. `dayjs` is still used for date *math* in `apps/web/src/features/recordings/stream-recordings-page.tsx`.

## Adding or changing a string

1. Add the key to `apps/web/messages/en.json`, the source of truth.
2. Add it to **every** other locale file. `pnpm i18n:check` (`scripts/i18n-check.mjs`, also run in CI) fails on missing or extra keys. It doesn't catch strings that were copied over in English and never translated.
3. If you can't translate it, copy the English value and say so in the PR description.

If the string changes a user-visible feature, update `docs/FEATURES.md` in the same change.
